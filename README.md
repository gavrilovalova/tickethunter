# Ловец билетов (Вахтанговский театр)

Личный Telegram-бот: следит за страницами спектаклей vakhtangov.ru и
присылает уведомление со ссылкой на покупку, когда появились билеты
или открылась новая дата. Работает на GitHub Actions, раз в ~5 минут.

## Запуск с нуля

1. **Бот.** В Telegram открыть @BotFather → `/newbot` → получить токен.
2. **chat_id.** Сначала написать своему боту любое сообщение — иначе
   `getUpdates` вернёт пустой `result`. Затем открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять число из
   `result[0].message.chat.id`.
3. **Репозиторий.** Рекомендуется **публичный** репозиторий: для публичных
   репозиториев GitHub Actions бесплатны без лимита минут. Секретов в
   репозитории нет — токен и chat_id лежат в Secrets (шаг 4). Наружу видны
   только код и `state.json`, то есть список отслеживаемых спектаклей и
   статусы их дат.
   Если хочется приватный репозиторий: бесплатного лимита (2000 минут/мес)
   хватит только при интервале раз в ~30 минут — поменять cron в
   `.github/workflows/watch.yml` на `"*/30 * * * *"`. При текущем `*/5`
   минуты закончатся примерно через неделю. Либо нужен платный план GitHub.

   Создать репозиторий на GitHub, затем из папки с кодом:

   ```
   git remote add origin <url-репозитория>
   git push -u origin main
   ```

   Код должен оказаться в ветке по умолчанию (`main`): расписание (`schedule`)
   GitHub запускает только из неё.
4. **Секреты.** Settings → Secrets and variables → Actions →
   добавить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
5. **Проверка.** Сначала отправить боту ссылку вида
   `https://vakhtangov.ru/show/maskarade/`. Затем вкладка Actions →
   workflow `watch` → Run workflow: ручной запуск обработает сообщение сразу.
   Подтверждение подписки придёт в течение нескольких минут; при обычном
   цикле ожидание ответа — до ~12 минут.

## Команды бота

- ссылка на `vakhtangov.ru/show/…` — подписаться;
- `/list` — подписки и статусы дат, с кнопкой «Удалить».

## Как это работает

Каждые 5 минут workflow: забирает новые сообщения (`getUpdates`) →
скачивает страницы подписок → сравнивает со `state.json` → шлёт
уведомления о переходах «закончились → в продаже» и о новых датах →
коммитит обновлённый `state.json`.

## Нюансы

- GitHub cron не точен: реальный интервал 5–12 минут.
- GitHub может автоматически отключать schedule-workflow после ~60 дней
  без активности (документировано для публичных репозиториев). Если бот
  затих — проверь вкладку Actions и перезапусти workflow.
- Ответ бота на команды приходит с задержкой до одного цикла.
